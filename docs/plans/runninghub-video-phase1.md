## 计费规则

按 RunningHub 实际运行时间结算，不按用户请求的视频成片时长结算。

上游成本：

| 档位 | 成本 |
| --- | ---: |
| Standard | 6 元/小时 |
| Plus | 8 元/小时 |
| Ultra | 16 元/小时 |

Lite 暂不接入。

建议销售价：

| 档位 | 成本价 | 销售价 |
| --- | ---: | ---: |
| Standard | 6 积分/小时 | 9 积分/小时 |
| Plus | 8 积分/小时 | 12 积分/小时 |
| Ultra | 16 积分/小时 | 24 积分/小时 |

平台按 `usage.taskCostTime` 计算实际运行时间。`consumeCoins` 和 `consumeMoney` 作为上游成本和审计数据保存。任务采用预扣、成功后核算、多扣退款、少扣补扣；失败或确认取消时退款；无法确认上游状态时进入待核对。

价格字段是整数 microcredits/秒，1 积分为 1,000,000 microcredits。小时价格换算到最接近的整数如下，存在不足 0.002 积分/小时的舍入误差：

| 档位 | 售价 microcredits/秒 | 成本 microcredits/秒 | 上游 instanceType |
| --- | ---: | ---: | --- |
| Standard | 2500 | 1667 | default |
| Plus | 3333 | 2222 | plus |
| Ultra | 6667 | 4444 | ultra |

算力档位由管理员模型能力 `video.executionTier` 固定，与分辨率 `vquality` 独立。三个档位应配置为三个模型条目，可指向同一工作流；浏览器不能覆盖系统模型的档位。预扣仍按提交时的计价数量估算，成功后按实际运行秒数向上取整结算；实际费用超过授权上限、usage 无效或补扣失败时转待核对。

生产三个模型已配置上述秒单价：原 Standard 模型保留名称、ID 与智墨H3标签，新增 Plus/Ultra，均指向同一工作流。Standard 的能力未显式填写档位时由服务端按 standard 执行。

## 后续扩展

RunningHub Provider 与具体工作流定义分离。后续通过新增或替换工作流定义支持图片、音频和其他视频工作流，包括版本、节点映射、输入字段、输出节点和默认参数，不为每个工作流重复实现请求代码。

## 验收标准

- 管理员可以配置 API Key；
- 系统视频模型列表能选择 RunningHub 模型；
- 自动做剧可以选择并提交该模型；
- 当前工作流能接收提示词、时长、比例、分辨率及参考素材；
- RunningHub 任务成功后视频被保存为影策资源；
- 失败、取消、超时不会继续显示生成中；
- 计费使用实际运行时间，并正确记录成本、售价、退款和利润；
- API Key、数据库、OSS 和线上账号数据不进入代码仓库。

### 剩余验收与恢复条件

取消验收须遵守现有任务合同：用户只能取消排队或本地准备阶段，进入上游提交、生成或媒体保存阶段后不允许取消；父任务失败、父任务取消及 worker context 的内部协调仍可请求上游取消并对账。不得为验证退款放开用户提交后的取消限制。工作台活动任务列表已复用 `canCancelGenerationTask`，上游提交后的“作品创作中”等阶段不再显示取消入口；16 项取消边界专项通过，后台取消合同未放宽。

本地新增取消集成验收复用真实准入、取消协调器、数据库、账单与积分流水，只模拟上游 HTTP：排队重复取消只退一次且没有上游请求；内部取消先获得接收回执但不退款，随后分别覆盖 `CANCELLED`、`CANCELED`、`FAILED`、`SUCCESS`、`RUNNING` 与 `1004`。确认取消/失败退回一次；已完成按 81.1 秒向上取整为 82 秒同时结算售价与成本；仍运行继续冻结并安排回查；任务丢失停止自动对账并转待核对。专项通过，前端取消显示边界 16 项通过。这是隔离本地证据，不代替生产取消退款或余额动态刷新验收；没有改动生产实现或资金。
