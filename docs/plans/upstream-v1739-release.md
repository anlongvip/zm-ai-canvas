# v1.7.3.9 上游同步发布验收

## 发布目标

从二开生产基线 `v1.7.3.8` 升级，整合作者提交 `dc035d51`，保留 RunningHub 接入、档位、实际运行时间计费、任务恢复及 Agent 维护保护。PR #8 负责集成；不能直接以作者的版本号覆盖二开发版历史。

## 发布前检查

- 最终提交在干净工作区运行 `bun scripts/verify-before-push.mjs` 默认范围；Linux 验证入口见 [本地环境](local-ci-environment.md)。
- PR 的最终 SHA 必须通过 Quality checks，包括支付双架构检查。
- 合入后生成自己仓库的 `v1.7.3.9` Release；核对 Web、Backend、yingce-agent 镜像版本、revision 和 digest，以及 Host Updater 二进制、SHA256SUMS、生产 Compose。
- 部署前只读核对实际 Compose、旧镜像、备份、数据挂载、Host Updater、可用空间及活动任务；保留当前与回退版本。

## 数据与回退

本次 Schema 从 77 升至 78，增加短剧角色声音、造型及镜头造型字段。Host Updater 应先排空、停服，再生成最终数据库和数据目录备份，迁移成功后启动目标版本并完成健康稳定窗口。失败须恢复升级前快照及旧配置、镜像；不可让旧版直接连接新 Schema。

保留原渠道 Key、价格、用户、余额、任务历史、OSS 和资源文件。测试默认复查已有任务与视频，不重复提交收费生成，不修改历史账务。RunningHub 真实取消退款仍需真实平台终态证据；模拟测试不能替代此验收。

## 生产验收要求

1. 三个业务镜像均匹配目标 Release，五个长期服务健康，迁移完成，Host Updater active。
2. readiness 返回目标版本/提交、`ready=true` 和 Schema 78/78；确认维护状态解除。
3. 已有登录态可使用，管理员更新页与用户页面可加载。
4. RunningHub 原任务、费用、钱包和三档模型配置保留，历史资源可访问并播放，刷新后仍保留。
5. 检查启动及业务错误日志；记录真实通过项和未覆盖项。
